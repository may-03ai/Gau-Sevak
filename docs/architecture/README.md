# Architecture Documentation

This directory records the proposed system boundaries and architecture baseline. It is not an approval to implement or deploy. The supplied V2.0 PDF is the broad product blueprint; V2.1 is a corrective override pack, not a full replacement. Apply V2.1 to conflicts and retain non-conflicting V2.0 requirements with provenance.

Use the individual documents here for system, data, payment, security, and integration views. Record consequential decisions in `docs/adr/` with status, context, decision, consequences, alternatives, owners, and references to source pages. Track unresolved decisions and approvals in `docs/implementation/technical-decisions.md`.

Distinguish source-stated constraints from proposed architecture, owner-approved decisions, implementation evidence, and specialist approval. A source document's assertion that a control is compliant or production-ready is not proof of approval or implementation. Never resolve a legal, tax, banking, payment-provider, or privacy question by inference.
